# TERP

T is a modular open-source ERP. The JavaFX **host** loads business features from plugin JARs; plugins depend only on the public SPI.

GPL-2.0. Source: [github.com/LeanAcademy/terp](https://github.com/LeanAcademy/terp)

## Modules

| Module | Role |
| --- | --- |
| `terp.plugin` | Public SPI: `IPlugin`, `TerpApplication`, desktop/menu/DAO contracts |
| `terp` | Host: login, desktop, Hibernate, plugin loader |
| `terp.core` | Reference plugin: company/branch, document series, VAT rates (`plugins/terp.core.jar`) |
| `terp.stok` | Stock plugin (material, warehouse, movement reasons, movements, on-hand report), installed as `plugins/terp.stok.jar` |
| `terp.cari` | Current-account plugin (cari kartı, movements, balance); one code as customer and/or supplier (`plugins/terp.cari.jar`) |
| `terp.satin` | Purchasing plugin: purchase request → purchase order → goods receipt → purchase invoice (`plugins/terp.satin.jar`) |
| `terp.satis` | Sales plugin: quotation → sales order → delivery note → invoice (`plugins/terp.satis.jar`) |
| `terp.uretim` | Production plugin: bill of materials / recipe (`plugins/terp.uretim.jar`) |

Future business modules (finance, HR) should be separate plugin JARs. Do not add their screens to the host. Keep `IDatabaseFactory` small (geography lookups); plugin-owned tables use `IPlugin.getPersistentClasses()` and `TerpApplication.getPersistence().createDao(...)`.

## Requirements

- JDK 17
- Maven 3.8+

## Build and run

```bash
git clone https://github.com/LeanAcademy/terp.git
cd terp
cp terp/etc/hibernate.properties.example terp/etc/hibernate.properties
mvn package
mvn -pl terp javafx:run
```

The host uses `terp/` as the application home. Override with `-Dterp.home=/path/to/terp`.

| Directory | Contents |
|-----------|----------|
| `etc/` | Config (`hibernate.properties`) and embedded Derby data (`etc/terp/`) |
| `lib/` | Extra JDBC driver JARs (PostgreSQL, MySQL, …). Not Derby: that comes from Maven. |
| `plugins/` | Plugin JARs (`terp.core.jar`, …) |

Any database with a **Java JDBC driver** can be used. Configure URL, dialect, user and password in `terp/etc/hibernate.properties`.

Drivers are discovered in this order:

1. JDBC 4 drivers already on the module path (Apache Derby is bundled for a local default)
2. `*.jar` files in `terp/lib/`
3. Extra JARs in `terp.jdbc.driver.jars` (comma-separated, also accepts the old `driver.jarfile.name` key)
4. Optional `hibernate.connection.driver_class` for older drivers without a JDBC 4 service file

Default sample setup is embedded Derby at `terp/etc/terp`. `hibernate.hbm2ddl.auto` is `update` so the schema is not wiped on each start. See `terp/etc/hibernate.properties.example` for PostgreSQL, MySQL, SQL Server and Oracle.

## Writing a plugin

1. Depend on `com.terp:terp.plugin`.
2. Implement `com.terp.plugin.IPlugin` (`getSystemVersion()` must be `1.0`).
3. Register it:

   `META-INF/services/com.terp.plugin.IPlugin`  
   `com.example.myplugin.Plugin`

4. Package a JAR and copy it to `terp/plugins/`, or use **Sistem yönetimi → Eklenti yönetimi** (`PluginInstaller`) in the host: list, **Ekle**, **Çıkar**. Removing a plugin deletes the JAR and the `eklenti` row; menus and business tables stay. Core plugins (`getType() == 1`, `terp.core`) cannot be removed. Restart after add/remove so Hibernate maps (or drops from the session) plugin entities.
5. Return entity classes from `IPlugin.getPersistentClasses()`. Declare menus with `IPlugin.getMenus()` (`PluginMenu.folder` / `PluginMenu.program`); the host inserts missing `menu` rows at bind time. The host popup menu (toolbar ☰) opens users, company, branch, working period, database connection, SQL (administrators), settings (menu, theme, font, table density), and exit. Open screens with `IPlugin.loadProgram(fxmlName)` using FXML from the plugin JAR. Set the FXML class loader to the plugin class loader. Access plugin tables with `TerpApplication.getInstance().getPersistence().createDao(MyEntity.class)` — do not add methods to `IDatabaseFactory`.

`terp.stok` is the stock plugin: material master (`ItemForm` / `malzeme`), stock movements (`MovementForm` / `stok_hareket`), stock count (`CountForm` / `stok_sayim`), and on-hand report (`StockStatusForm`). Warehouses (`WarehouseForm` / `depo`, STK03), movement reasons (`ReasonForm` / `hareket_neden`, STK06), and VAT rates (`VatRateForm` / `kdv_oran`, SYS08) are under **Sistem yönetimi**. `hareket_turu` is only in/out. Transfer writes one çıkış (`TRANSFER_CIKIS`) and one giriş (`TRANSFER_GIRIS`) sharing a `TR-` series number; count and scrap are reasons (`SAYIM_ART`, `SAYIM_AZ`, `FIRE`, `ALIM`, `SATIS_IRS`, `URETIM_SARF`, …). Other plugins must not import stock entity classes; they post and reverse through `IStockLedger` / `StockPosting` (`sourceType` + `sourceId`). After `mvn -pl terp.core,terp.stok,terp.cari,terp.satin,terp.satis,terp.uretim package` the JARs are under `terp/plugins/`. `terp.cari` owns the current-account master (`AccountForm` / `cari`), movements (`AccountMovementForm` / `cari_hareket`, CRI03), and balance (`AccountStatusForm`, CRI04). Other plugins post and reverse through `IAccountLedger` / `AccountPosting` (`sourceType` + `sourceId`); never import `Cari` / `AccountMovement`. `terp.uretim` owns the bill of materials (`RecipeForm` / `uretim_recete`, URT02): one recipe per finished or semi-finished item, components are raw / semi / consumable, yield quantity on the header. Production orders (`ProductionOrderForm` / `uretim_emri`, URT03) explode that recipe into an editable material pull list. Completions (`ProductionCompletionListForm` / `uretim_bitis`, URT04) are posted from a separate **İş bitti** menu, in parts. Each completion posts `URETIM_SARF` outbound for consumed qty and `URETIM_GIRIS` inbound for produced qty (`sourceType=URETIM_BITIS`); cancel reverses. When posted produced qty covers the planned qty the order becomes **Kapalı**. Standalone orders are allowed. Sales **Üretim emrine çevir** opens a draft for the first remaining recipe line through `IProductionOrders` (codes/qty only). `terp.satin` owns purchasing documents: request (`RequestForm` / `satin_talep`), order (`OrderForm` / `satin_siparis`), order status (`OrderStatusForm`, SAT05: ordered / posted received / remaining per item), goods receipt (`ReceiptForm` / `satin_kabul`, SAT02), and purchase invoice (`PurchaseInvoiceForm` / `satin_fatura`, SAT07). Receipts from an order open as a dialog from the order list or from **Mal kabul → Siparişten mal kabul**. Purchasing settings (`SettingsForm` / `satin_ayar`, SAT06) are under **Sistem yönetimi**. Approve a request, then **Siparişe çevir** copies lines into a draft order (supplier + warehouse required). Approve an order, then **Mal kabule çevir** or **Siparişten mal kabul** copies remaining quantities into a draft goods receipt; quantity is editable up to the over-receipt percent. Several receipts may be posted against one order; the order status becomes **Kapalı** when posted qty covers every line. Order approve does not write stock. Receipt draft save writes no stock; approve posts `TYPE_IN` with reason `ALIM` and `sourceType=SATIN_KABUL`; cancel reverses stock (and leftover `SATIN_KABUL` cari from older rows). **Faturaya çevir** or **Mal kabulden fatura** copies remaining received quantities into a draft invoice; quantity cannot exceed the uninvoiced receipt balance. Invoice approve does not write stock; it posts a supplier credit through `IAccountLedger` (`sourceType=SATIN_FATURA`) for qty × price including VAT; cancel reverses. Several invoices may be posted against one receipt; the receipt status becomes **Faturalandı** when posted invoice qty covers every line. Standalone receipts and invoices remain allowed. Receipt, purchase invoice, and sales invoice keep a system number from the series and a separate official document number (`evrak_no`). Invoice lines keep the VAT % from the material card (editable); footers show net, VAT, and gross. `terp.satis` owns quotation (`SalesQuoteForm` / `satis_teklif`, STS06), sales order (`SalesOrderForm` / `satis_siparis`, STS03), order status (`SalesOrderStatusForm`, STS04: ordered / posted delivered / remaining per item), delivery (`DeliveryForm` / `satis_irsaliye`, STS02), and invoice (`InvoiceForm` / `satis_fatura`, STS05). Quote and invoice lines keep the VAT % from the material card (editable); footers show net, VAT, and gross. Customer and warehouse are required on quote, order and delivery. Quote approve does not write stock or cari. **Siparişe çevir** copies quote lines into a draft order; one open order per quote. Order approve does not write stock. **Üretim emrine çevir** opens a production order for a remaining finished/semi line that has an active recipe. **İrsaliyeye çevir** or **Siparişten irsaliye** copies remaining quantities into a draft delivery; quantity cannot exceed remaining. Several deliveries may be posted against one order; the order status becomes **Kapalı** when posted qty covers every line. Delivery draft save writes no stock; approve posts `TYPE_OUT` with reason `SATIS_IRS` and `sourceType=SATIS_IRS`; cancel calls `reverseByDocument`. **Faturaya çevir** or **İrsaliyeden fatura** copies remaining delivered quantities into a draft invoice; quantity cannot exceed the uninvoiced delivery balance. Invoice approve does not write stock; it posts a customer debit through `IAccountLedger` (`sourceType=SATIS_FATURA`) for qty × price including VAT; cancel reverses. Several invoices may be posted against one delivery; the delivery status becomes **Faturalandı** when posted invoice qty covers every line. Standalone deliveries and invoices (no source document) remain allowed. Stock count (STK07) is a header+line document: **Depodan doldur** loads non-zero on-hand into counted (editable); approve posts `COUNT_IN`/`COUNT_OUT` with `SAYIM_ART`/`SAYIM_AZ` and `sourceType=STOK_SAYIM` for the difference vs live on-hand; cancel reverses. Manual STK04 count lines stay unbound to the document. Material, warehouse, movement, reason, cari, request, order, receipt, purchase-invoice, stock-count, sales-quote, sales-order, sales-delivery, sales-invoice, production-order, account-movement, and document-series numbers are unique per selected company (`firma_ref`). Document series (`SeriesForm` / `belge_seri`, SYS07) live under **Sistem yönetimi**; draft save of request, order, receipt, purchase invoice, stock count, sales order, sales delivery, sales quote, sales invoice, production order, stock transfer, and manual current-account movement allocates the next number when the field is blank (typed numbers do not increment the series). A material can store many supplier/customer item codes (`malzeme_cari_kod`); each row is one partner’s own stock code and name, chosen from `IAccountLookup`. Lookups: `IItemLookup`, `IWarehouseLookup`, `IMovementReasonLookup`, `IAccountLookup`, `IAccountLedger`, `IDocumentNumbers`, `IVatRateLookup`, `IProductionOrders`.

Users belong to one group (`grup`). The **Administrators** / sistem group sees every company and program. Other groups get companies (`grup_firma`) and program CRUD (`grup_yetki`) from **Sistem yönetimi → Yetki yönetimi**. Put people into groups with **Kullanıcılar**. The toolbar company combo is the active firm for the session.

The host scans `plugins/*.jar` with `URLClassLoader` + `ServiceLoader`. It does not use a Java agent.

## Türkçe

T, eklenti tabanlı açık kaynak bir ERP iskeletidir. Java 17 ve Maven ile `mvn package` ardından `mvn -pl terp javafx:run` yeterlidir. Eklenti JAR dosyalarını `terp/plugins/` altına koyun veya Sistem yönetimi → Eklenti yönetimi ile ekleyin/çıkarın; entity içeren eklentiler için uygulamayı yeniden başlatın (`hbm2ddl=update`). Çıkarma JAR ve `eklenti` kaydını siler, menü ve iş tablolarına dokunmaz. Kullanıcılar gruplara bağlıdır; sistem grubu dışında şirket ve işlem yetkisi Yetki yönetimi ekranından verilir. Ana araç çubuğunda açık listedeki tablolar **Yazdır** ve **Excel'e aktar** ile alınır; programlar sol menüden açılır. ☰ **Ayarlar** temasını, yazı tipini, puntoyu ve tablo sıklığını `application.properties` içinde saklar. Malzeme, cari, depo, neden, satınalma talep/sipariş, mal kabul, alım faturası, stok sayım, satış teklifi, satış siparişi, satış irsaliyesi, satış faturası, üretim emri ve cari hareket belge numaraları seçili firmaya (`firma_ref`) bağlıdır; boş bırakılırsa taslak kaydetmede `belge_seri` numaratörü basar (Sistem yönetimi → Belge numaraları). KDV oranları (`terp.core`, SYS08 / `kdv_oran`) Türkiye oranlarıyla (0 / 1 / 10 / 20) firma bazında tohumlanır; malzeme kartı bu listeden seçer. Cari kartı (`terp.cari`) her hesaba firma içinde tek kod verir; cari hareket borç/alacak fişi basar, cari durum bakiyeyi gösterir. Malzeme kartındaki tedarikçi/müşteri stok kodları ayrı tabloda, cari başına kod ve ad olarak tutulur. Stok eklentisi depo tanımı, hareket nedeni, giriş/çıkış/transfer/sayım/fire yönleri, stok sayım belgesi ve stok durum raporunu içerir; transfer belge no `TR-` serisinden basılır; bakiye hâlâ yönle hesaplanır. Sayım onayında eldeki ile sayılan fark `SAYIM_ART` / `SAYIM_AZ` fişi basar; elle STK04 sayım satırı belgeye bağlanmaz. Satınalma (`terp.satin`) talep → sipariş → mal kabul → alım faturası akışını kullanır; sipariş durumu ekranı sipariş/malzeme bazında sipariş, teslim ve kalan bakiyeyi gösterir; siparişten mal kabul menüden veya sipariş ekranından açılır, miktar bakiyeden gelir ve düzenlenebilir, sipariş bakiyeye göre kapanır, fazla kabul oranı satınalma ayarlarında tutulur. Mal kabul onayında `IStockLedger` ile `ALIM` nedenli giriş fişi basar, stok yazar, cari yazmaz. Mal kabul, alım faturası ve satış faturasında sistem no numaratörden, resmi belge no ayrı alandan gelir. Alım faturası satır KDV’si ve ara toplam / KDV / genel toplam gösterir; onayda stok yazılmaz, tedarikçiye `IAccountLedger` ile KDV dahil alacak fişi basar, iptalde geri alır; mal kabul bakiyeye göre **Faturalandı** olur. Bağımsız mal kabul ve alım faturası da yazılabilir. Üretim (`terp.uretim`) reçete kartı mamul/yarı mamul başına bileşen listesi tutar; üretim emri reçeteyi patlatıp düzenlenebilir çekme listesi oluşturur; iş bitti ayrı menüden (URT04) parça parça onaylanır, her bitişte `URETIM_SARF` sarf ve `URETIM_GIRIS` giriş fişi basar, plan dolunca emir kapanır. Onaylı satış siparişi üretim emrine çevrilebilir. Satış (`terp.satis`) teklif → sipariş → irsaliye → fatura akışını kullanır; teklif ve faturada satır KDV’si ve ara toplam / KDV / genel toplam görünür; onaylı teklif siparişe çevrilir (teklif başına bir açık sipariş), stok ve cari yazılmaz. Sipariş durumu ekranı sipariş/malzeme bazında sipariş, teslim ve kalan bakiyeyi gösterir; siparişten irsaliye menüden veya sipariş ekranından açılır, miktar bakiyeden gelir, sipariş bakiyeye göre kapanır. Bağımsız irsaliye ve fatura da yazılabilir. İrsaliye onayında `SATIS_IRS` nedenli çıkış fişi basar, iptalde geri alır. Fatura onayında stok yazılmaz; müşteriye `IAccountLedger` ile KDV dahil borç fişi basar, iptalde geri alır; irsaliye bakiyeye göre **Faturalandı** olur. JDBC sürücü JAR dosyalarını `terp/lib/` altına koyup `hibernate.properties` içinde URL ve dialect ayarlayın.
